# 모아봄 vs 단일 AI (GPT·Gemini) — 발표용 핵심 3

> **포지셔닝 한 줄**
> GPT·Gemini는 *물어보면 그럴듯하게 답하는 LLM*,
> 모아봄은 *실제 데이터를 수집·교차검증·집계해 판정을 내려주는 분석 시스템*.
>
> 같은 링(챗봇 vs 챗봇)에서 싸우지 않는다. **"범용 LLM vs 도메인 분석 파이프라인"** 으로 비교 축을 끌고 간다.

---

## 발표에서 강조할 3개 (각 ~10초)

### 1. 환각이 아니라 실측
- **한 줄:** "GPT는 기억으로 추측하고, 모아봄은 실제 영상·댓글을 그 자리에서 수집해 답합니다."
- **근거:** 영상 N개 자막 + 댓글 수천 건 실시간 수집 → 출처 추적 가능(영상 N개·댓글 N/N 빈도·대표 댓글 원문).
- **킬러 포인트:** GPT는 출처가 없고 컷오프가 있다. 모아봄은 **어제 나온 폰도** 분석하고, **왜 그렇게 판단했는지 클릭해서 검증**할 수 있다.

### 2. 한 모델의 의견이 아니라, 다중 검증된 판정
- **한 줄:** "GPT에 묻는 건 1표, 모아봄은 여러 AI가 교차검증한 합의입니다."
- **근거:** 7-step 멀티 에이전트(영상 선정 + 댓글 필터링) → 다중 LLM 교차검증 → 환각 방지 4규칙. 실패 시 "데이터 부족" 정직 모드로 자동 전환.
- **킬러 포인트:** 단일 LLM의 최대 약점은 **자신감 있는 오답**. 모아봄은 1차 소견이 아니라 **협진**이고, 모르면 모른다고 말한다.

### 3. 쓸수록 똑똑하고 싸지는 구조
- **한 줄:** "단일 LLM은 쓸수록 비싸지지만, 모아봄은 쓸수록 싸집니다."
- **근거:** 댓글 감성분석을 로컬 모델(KLUE-BERT) 하이브리드로 전환(Break-even ~1.24만 댓글/일) + RAG로 근거 검색 + DB 의존도 축소.
- **킬러 포인트:** 작업 난이도별 모델 라우팅(단순 분류는 로컬, 복잡 판단만 LLM) → **특정 LLM에 인질로 잡히지 않는다.**

## 마지막 한 방 — 가장 직관적인 마무리

> **"영상 5개를 정주행하고 댓글 수천 개를 다 읽으면 2시간.**
> **모아봄은 그걸 한 장의 보고서로 줍니다."**

- GPT의 답 = **읽는 줄글**, 모아봄의 답 = **보는 보고서**
  (구매 판정 → 6차원 평가표 → 합의 장단점 → 소비자 여론 → 추천/비추, 그리고 PDF로 저장)
- 핵심 대비를 마지막 한 문장으로:
  **"추측을 읽지 말고, 집계된 판정을 보세요."**
